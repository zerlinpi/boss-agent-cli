# 招聘数据生命周期

Web 控制台使用本地文件保存岗位、候选人评估、回复草稿、任务历史和审计日志。本文说明数据的创建、更新、删除和备份边界。

## 数据位置

默认目录：

```text
~/.boss-agent/recruiter-ai/
```

主要内容：

```text
jobs/                 岗位 JD 和评分规则
evaluations/          候选人简历、评分证据和人工阶段
replies/              待人工审核的回复草稿
web_tasks.db          Web 后台任务历史
audit.jsonl           关键操作审计记录
```

## 候选人版本与去重

BOSS 候选人使用平台提供的稳定候选人/会话标识。本地文件上传使用：

```text
文件名 + 候选人名
```

生成稳定来源键。简历内容指纹只用于判断内容是否变化：

- 文件未变化：跳过重复 AI 评估；
- 同一文件内容更新：生成新评估版本；
- 排行榜与报告：仅使用该候选人的最新版本；
- 删除候选人：清理该稳定来源键下的全部评估版本和关联草稿。

为避免将不同候选人错误合并，本地批量导入时应保留唯一、稳定的文件名，例如：

```text
candidate-001-zhang-san.pdf
candidate-002-li-si.docx
```

## 隐私处理

发送给 AI 模型前，系统会递归清理：

- 候选人姓名；
- 手机号；
- 邮箱；
- 微信号；
- QQ；
- 身份证号；
- 年龄、性别、照片、婚育等受保护属性；
- 嵌套字段和 PDF/DOCX/TXT 自由文本中的上述内容。

回复草稿生成时，候选人身份和联系方式同样会从评估上下文与聊天上下文中移除。回复记录落盘前会再次脱敏。

本地原始评估记录仍可能包含招聘人员有权处理的简历内容，因此应把 `~/.boss-agent` 目录视为敏感业务数据并限制操作系统访问权限。

## 删除

### 删除候选人

候选人详情底部提供“永久删除”。操作会删除：

- 该逻辑候选人的全部历史评估；
- 与这些评估关联的全部回复草稿。

审计日志只保留删除动作和数量，不保留候选人姓名或人工备注原文。

### 删除岗位

岗位卡片提供“删除”。操作会删除：

- 岗位 JD 和评分规则；
- 岗位下全部候选人评估；
- 与这些评估关联的回复草稿。

任务历史和审计日志不会级联删除，用于证明发生过相应操作，但其中不保存 AI Key 或完整简历正文。

删除不可撤销。执行删除前应根据公司数据保留政策决定是否备份。

## 备份与恢复

停止 Web 控制台后，复制整个数据目录即可完成一致性备份：

```text
~/.boss-agent/
```

恢复时：

1. 关闭 Web 控制台；
2. 将备份覆盖回原数据目录；
3. 重新启动控制台；
4. 在“任务与审计”确认历史记录可读取。

任务数据库使用 SQLite WAL 模式。进行文件级备份时应停止服务，或同时复制：

```text
web_tasks.db
web_tasks.db-wal
web_tasks.db-shm
```

## BOSS 登录是否必需

本地简历筛选不要求登录 BOSS。首次引导中的 BOSS 登录属于可选步骤，仅在需要读取授权范围内的 BOSS 投递、在线简历或聊天上下文时使用。
