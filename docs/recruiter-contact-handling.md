# 招聘联系人数据处理

招聘工作台将“本地人工操作数据”和“发送给 AI 的决策数据”分开处理。

## 本地保留

以下信息可以保存在本机，用于人工联系候选人：

- 姓名；
- 电话和座机；
- 邮箱；
- 微信；
- QQ；
- 招聘阶段和人工备注；
- 人工粘贴、用于招聘沟通的聊天内容。

候选人详情页会显示提取到的联系方式，并提供复制入口。

本地简历副本还可能保留原始年龄、性别、婚姻状况等字段供人工查看，但这些字段不进入 AI 评分输入，也不能被配置成评分规则。

### 本地也不保留的高风险身份数据

以下内容不属于日常约面所必需的数据，会在标准化、直接 Store 写入和 reply conversation 持久化边界统一清理：

- 身份证号，包括连续格式和常见空格/短横线格式；
- `passport / passportNo / 护照号` 等结构化护照字段；
- 带明确“护照号 / passport number”等标签的护照号码；
- 家庭住址、家庭地址、现住址、现居住址、居住地址、住宅地址、详细住址等住宅详细地址。

电话、邮箱、微信、QQ 等人工联系渠道仍可保留。`面试地址`、公司办公地址等招聘流程信息不会因为住宅地址规则被自动删除。

直接调用 `RecruiterAIStore.save_evaluation()` 或 `find_unchanged()` 也执行同一清理策略，因此不能通过绕过 Web/CLI 标准化入口重新写入上述高风险身份数据。

## AI 输入

AI 评分、推荐和回复草稿使用单独生成的模型安全副本。发送模型前会隔离：

- 姓名；
- 电话、座机、邮箱、微信、QQ；
- 身份证号、护照号和住宅详细地址；
- 婚姻状况；
- 年龄、出生日期；
- 性别；
- 民族、种族、国籍；
- 政治面貌、政治身份、党派；
- 宗教；
- 健康、疾病、残障；
- 怀孕、生育、生育计划等相关状态。

字段匹配同时覆盖常见 `snake_case`、`camelCase`、中文字段名、英文别名和自由文本。自由文本中的紧凑表达，例如 `31岁 | 男 | 已婚`、`中共党员`、`已育一子`、宗教或残障描述，也会在模型请求前隔离，同时尽量保留 Java 年限、项目规模、职责和量化成果等岗位证据。

模型侧的身份证识别还覆盖常见空格/短横线格式，例如：

```text
110101 19900101 1234
110101-19900101-1234
```

## 评分规则边界

模型输入脱敏之外，本地评分规则本身也有强制门禁。以下内容不能作为：

- 评分维度；
- 硬性要求；
- 自由评分 instructions；
- AI 生成的候选人画像条件；
- 建议面试问题。

禁止使用的标准包括年龄、性别、婚育、民族/种族、宗教、政治身份、健康/残障、照片/外貌等个人属性，以及 `90后 / 年轻优先 / under 30` 等年龄代理条件。

候选人的工作稳定性只能依据岗位相关证据，例如任职时长、工作切换频率、履历空档、项目持续时间和职责连续性，不使用婚姻状态、年龄或性别作为评分依据。

## 模型输出边界

输入脱敏不能保证模型永远不自行生成不当内容，因此评分结果还会经过本地输出过滤：

- 维度 evidence/reason；
- 硬性要求 evidence；
- strengths / concerns；
- next questions；
- summary。

如果模型自行生成受保护属性或联系方式内容，相应内容会被移除；违规 evidence 不能继续支撑正分，并把推荐结果强制降级为 `manual_review`。模型自行增加未配置的硬性要求也不会进入正式结果。

## 回复草稿

回复模型使用脱敏后的聊天上下文。模型返回后还会经过确定性本地安全扫描，标记：

- 受保护属性询问；
- 确定录用或 Offer 承诺；
- 联系方式异常暴露；
- 身份证、护照、住宅地址等高风险身份数据暴露；
- 异常长回复。

所有草稿都要求人工审核，系统不会自动发送。

保存 reply record 时，聊天中电话、邮箱、微信、QQ 等人工约面联系方式可以继续保留；身份证、护照和住宅详细地址会在落盘前移除。

## 历史数据

新的模型隔离和评分规则约束适用于后续评分、重评和草稿生成。此前已经在持久化前删除的数据无法从现有评估记录自动恢复，需要重新导入简历或重新获取候选人数据。

历史 evaluation 的候选人身份会在读取时按当前 canonical identity 归组；人工阶段和备注按逻辑候选人同步，不要求批量改写所有旧 JSON 才能继续使用。

历史记录如果基于旧 JD 或旧评分规则，会继续保留用于审计，但不会进入当前岗位排名/统计，也不能直接用于生成新的 AI 回复草稿；重新评估后才重新进入当前决策视图。
